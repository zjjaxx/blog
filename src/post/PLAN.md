# 布林带多周期价值投资 Skill 实施计划（PLAN）

> 依据文档：`boll.md`（同目录）
> 本文件只做规划，不含代码实现。未落地的内容均为"目标设计"。

---

## 1. 目标

构建一个标准化 Agent Skill（暂定名 `boll-value-quant`），把 `boll.md` 中的选股与交易规则变成**可复现、可回测、可日常扫描**的工具链：

1. **基本面选股**：通过 opencli（浏览器 / 自定义 adapter）抓取股息率、分红历史、经营现金流、市值、30 年国债收益率，按文档 4 条规则筛出股票池。
2. **行情数据**：使用 BaoStock 获取 A 股日线数据，本地缓存，统一做前复权并聚合成周线 / 月线。
3. **指标与信号**：实现 BOLL(20, 2)、%b、带宽、RSI(14)、MFI(10)、20 周均量，以及"一主两辅"六步交易规则。
4. **回测**：基于 PyBroker 的自定义 DataSource + 策略，输出绩效、交易明细、报告。
5. **日常扫描**：对股票池跑最新信号，输出"今日可关注 / 可进场 / 需离场"清单。

**核心原则：能固化成脚本的一律固化成脚本**。Skill 文档只负责编排流程和解释结果，计算逻辑全部放在 `scripts/` 中，Agent 不临时手写计算代码。

| 环节 | 方案 | 说明 |
| :--- | :--- | :--- |

| 测试 | `pytest` | 指标数值校验、信号规则用例 |

## 4. 数据层设计

### 4.1 行情：BaoStock

- **获取**：`query_history_k_data_plus` 拉取日线 **不复权** 数据（`adjustflag="3"`），字段：`date, code, open, high, low, close, volume, amount, tradestatus, isST`。
- **复权**：同时拉取 `query_adjust_factor`，本地计算前复权。
  - 原因：BaoStock 的前复权基准随新的除权事件变化，直接缓存前复权价格会导致历史数据"漂移"；缓存原始价格 + 复权因子，可在每次使用时重新计算，结果一致。
- **增量更新**：按股票记录最后日期，只补新数据；检测到新的除权除息事件时重新计算该股的前复权序列。
- **停牌处理**：`tradestatus=0` 的日期剔除，不参与指标计算。
- **代码格式**：内部统一使用 BaoStock 格式（`sh.600000`），与 opencli 返回的代码做映射。

### 4.2 周线 / 月线聚合（防止未来函数）

- 由前复权日线聚合：open 取首日，high 取最高，low 取最低，close 取末日，volume 求和。
- 周线以"该周最后一个交易日"为标签，月线以"该月最后一个交易日"为标签。
- **映射回日线时**：某个交易日只能看到**已收盘完成**的周 / 月指标（最近一个已完成周期的值向前填充），保证回测时日线上看到的周线信号不包含当周未来数据。
- 周最后一个交易日当天收盘后，该周的指标才生效；离场、止损等"周收盘"决策在该日收盘判定，次一交易日开盘执行（可配置为当日收盘执行）。

### 4.3 基本面：opencli

现有 opencli 内置 adapter（`eastmoney quote/kline/holders`、`xueqiu stock` 等）**不覆盖**分红历史、现金流、市值筛选、30 年国债收益率，需要自建。

**流程（每个数据源都按此步骤）**：

1. 用 `opencli browser open` 打开目标页面（候选：东方财富数据中心分红送配页、个股 F10 财务分析页、选股器页、中国债券信息网 / 东方财富国债收益率页）。
2. 用 `opencli browser network` 抓包，定位返回 JSON 的数据接口与参数。
3. 用 `opencli browser init boll/<command>` 生成 adapter 骨架，按 `opencli-adapter-author` skill 的规范编写。
4. 优先 `PUBLIC` 策略（纯 HTTP）；接口需要 Cookie 时才降级为 `COOKIE`。
5. `opencli validate` + `opencli verify --smoke` 验证后，源码收录到 Skill 的 `adapters/`。

| adapter | 输出字段（目标） | 用途 |
| :--- | :--- | :--- |
| `boll screener` | 代码、名称、总市值、股息率(TTM)、行业 | 市值 ≥ 1000 亿初筛，缩小后续抓取范围 |
| `boll dividend <code>` | 年度、每股派息、现金分红总额、除权除息日 | 连续 3 年分红、近 3 年分红合计 |
| `boll cashflow <code>` | 年度、经营活动现金流量净额 | 现金流覆盖分红 |
| `boll bond-yield` | 日期、30 年期国债收益率 | 股息率门槛 = 2 × 收益率 |

**兜底**：BaoStock 自带 `query_dividend_data`（分红）和 `query_cash_flow_data`（现金流比率类数据），作为交叉校验来源；两者差异超过阈值时在报告中标注，不静默选一个。

### 4.4 基本面筛选规则（`screen.py`）

| 规则 | 精确定义 |
| :--- | :--- |
| 股息率 | 股息率(TTM) ≥ 2 × 最新 30 年国债收益率 |
| 连续分红 | 最近 3 个完整会计年度每年都有现金分红 |
| 现金流覆盖 | 近 3 年经营现金流净额合计 ≥ 近 3 年现金分红合计 |
| 市值 | 总市值 ≥ 1000 亿元 |

输出 `universe_YYYYMMDD.csv`，每行带上每条规则的原始值和是否通过，方便人工复核。

## 5. 指标定义（`indicators.py`）

全部基于前复权价格，参数来自 `config.yaml`。

| 指标 | 定义 |
| :--- | :--- |
| BOLL | 中轨 = SMA(close, 20)；上 / 下轨 = 中轨 ± 2 × 总体标准差（`ddof=0`，与布林格原定义一致） |
| %b | (close − 下轨) / (上轨 − 下轨) |
| 带宽 | (上轨 − 下轨) / 中轨 |
| RSI(14) | Wilder 平滑（与主流行情软件一致），在 reference 中注明 |
| MFI(10) | 按文档公式：典型价、资金流、正负资金流 10 期求和；典型价持平记为 0；负资金流为 0 时 MFI = 100 |
| 均量 | 最近 20 周成交量 SMA；"当周"是否包含在均量内需确定（见第 9 节） |
| 放量 / 缩量 / 恐慌抛售 | ≥ 1.5×、≤ 0.8×、收跌且 ≥ 2× 均量 |

日线、周线、月线三个周期都计算 BOLL；RSI、MFI、均量主要用于周线。

**验证**：用 2～3 只股票，与东方财富 / 同花顺显示的 BOLL、RSI 数值比对，误差在小数点后 2 位以内。

## 6. 交易规则精确化（`signals.py`）

把文档六个步骤实现为**按股票逐日推进的状态机**：`空仓 → W 底待确认 → 等待日线进场 → 持仓（情况 A / B）→ 离场`。

### 第一步：月线方向
- 变化率 = (当前月中轨 − 6 个月前月中轨) / 6 个月前月中轨。
- ≥ +5% 向上（仓位系数 1.0）；−5%～+5% 走平（仓位系数 0.5）；< −5% 向下（不开新仓）。
- 文档中"走平时不做挤压突破"：本策略本身没有挤压突破信号，记录为后续扩展点。

### 第二步：周线 W 底
- **低点识别**：周 %b ≤ 阈值的连续区间中，取 %b 最小的那一周作为该次低点。
- 第一个低点：%b ≤ 0.05。
- **中间反弹**：文档没有量化，默认定义为两个低点之间周 %b 最高值 ≥ 0.5（回到中轨），参数可配置。
- 第二个低点：距第一个低点 3～15 周；0 < %b ≤ 0.2 且高于第一个低点的 %b。
- 动量：第二个低点的 RSI > 第一个低点的 RSI。
- 资金：第二个低点的 MFI > 第一个低点的 MFI；第一个低点到第二个低点之间没有恐慌抛售周。
- 信号在第二个低点所在周**收盘确认**后生效。
- **信号有效期**：文档没有规定，默认 W 底确认后 8 周内等待日线进场，超时作废；期间周 %b 跌破 0 也作废。

### 第三步：日线进场
- 日中轨相对 5 个交易日前的变化率 ≥ −1%。
- 连续 2 个交易日收盘价 > 日中轨。
- 成交价：可配置为"第 2 日收盘"或"次日开盘"（默认次日开盘，更贴近实盘）。

### 第四步：止损与仓位
- 止损参考价 = 当前周下轨 − 0.1 × (周上轨 − 周下轨)。
- 股数 = 总资金 × 2% / (买入价 − 止损参考价) × 月线系数，**向下取整到 100 股**，且不超过可用现金。
- 买入价 ≤ 止损参考价（风险距离 ≤ 0）时放弃交易。
- 止损触发：周收盘 %b < −0.1 时全部卖出。

### 第五步：持仓期间
- 只在周最后一个交易日评估离场条件，日线信号不触发离场。
- 不加仓（文档提到加仓减仓，但没有给出规则，v1 不实现）。

### 第六步：离场（每周收盘按优先级判断）
1. 止损：%b < −0.1 → 全部卖出。
2. 情况 B 判定：连续 ≥ 3 周 %b ≥ 0.8 且带宽逐周扩大 → 进入"沿上轨行走"状态，之后 %b < 0.5 才离场。
3. 情况 A：%b ≥ 0.9，且周 RSI 或周 MFI 低于"上一个周线高点"（上一段 %b ≥ 0.9 区间中 %b 最高那一周）的对应值 → 全部卖出。
   - 持仓后第一次到达上轨时没有"上一个高点"可比较，默认回溯到建仓前最近一次 %b ≥ 0.9 的高点（可配置）。

### 输出
每只股票每个交易日输出一行：月线方向、W 底状态、进场信号、持仓状态、离场原因。回测与扫描共用这份输出，保证两边逻辑一致。

## 7. 回测设计（PyBroker）

- **DataSource**：继承 `pybroker.data.DataSource`，从本地缓存读取前复权日线，并把周 / 月指标和信号状态作为自定义列，通过 `pybroker.register_columns` 注册。
- **策略执行**：在 `Strategy` 的 `exec_fn` 中只读取预先计算好的信号列来下单，不在执行函数里重复计算规则。
  - 进场：`ctx.buy_shares = sizing(...)`，按配置的成交价执行。
  - 离场：读取当日的离场信号列，`ctx.sell_all_shares()`。
- **交易约束**：
  - A 股只能做多，T+1（PyBroker 默认次日成交可满足）。
  - 手续费：佣金万 2.5（最低 5 元），卖出印花税 0.05%，可配置。
  - 涨停不能买入、跌停不能卖出：v1 记录被跳过的交易次数，v2 再处理。
- **组合层**：`max_long_positions` 控制最大持仓数；同一天信号超出持仓上限时，按 W 底强度（例如两个低点 %b 差值）排序。
- **基准**：沪深 300 买入持有、股票池等权买入持有。
- **输出**：总收益、年化收益、最大回撤、夏普、胜率、盈亏比、平均持仓周数、交易明细（含进场原因、离场原因）、资金曲线图。
- **参数稳健性**（第二阶段）：对关键阈值（W 底 %b、月线 ±5%、止损 −0.1）做网格扫描，配合 PyBroker 的 walkforward，避免过拟合。

### 已知偏差（报告中必须注明）
- **前视偏差**：v1 用当前基本面快照筛出的股票池去回测历史行情，相当于"用今天的结果选过去的股票"，收益会被高估。
- **幸存者偏差**：已退市、已跌出 1000 亿市值的股票不在池中。
- v2 计划：按年度保存基本面快照（以年报披露日为生效日），回测时按日期使用当时的股票池。

## 8. Skill 使用流程（SKILL.md 中要写的标准工作流）

```
任务进度：
- [ ] 0. 环境检查：scripts/setup_env.sh（含 opencli doctor）
- [ ] 1. 抓取基本面：scripts/fetch_fundamentals.py
- [ ] 2. 筛选股票池：scripts/screen.py → universe.csv
- [ ] 3. 更新行情：scripts/fetch_bars.py --universe universe.csv
- [ ] 4a. 回测：scripts/backtest.py --start 2015-01-01 --end today
- [ ] 4b. 或扫描当前信号：scripts/scan.py
- [ ] 5. 生成报告：scripts/report.py
```

Agent 在 Skill 中的职责仅限于：
- 按顺序调用脚本，检查退出码与输出；
- adapter 失效时按 `opencli-autofix` 流程修复；
- 解读报告，用中文向用户汇报；
- **不**临时手写指标计算或规则判断代码。

触发场景（写入 description）：布林带选股、%b、W 底、高股息筛选、PyBroker 回测、BaoStock 数据、A 股价值投资信号扫描。

## 11. 风险与应对

| 风险 | 应对 |
| :--- | :--- |
| 网页接口变动导致 adapter 失效 | adapter 尽量对接 JSON 接口而不是页面 DOM；失效时走 `opencli-autofix`；BaoStock 兜底 |
| BaoStock 服务不稳定 / 限流 | 本地缓存 + 失败重试 + 断点续传 |
| 前复权数据漂移 | 缓存原始价格 + 复权因子，使用时再计算 |
| 周线信号混入未来数据 | 只映射已完成周期；单元测试专门校验 |
| 规则描述存在歧义 | 统一在 `reference/strategy-rules.md` 写明默认解释，并全部参数化 |
| 股票池小（满足 4 条的大盘高股息股可能只有几十只），样本少 | 报告中给出交易次数，样本不足时明确提示统计意义有限 |
